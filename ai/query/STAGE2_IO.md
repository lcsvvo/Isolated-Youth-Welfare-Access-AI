# 2단계 입력·출력 명세 (3번 BM25, 4번 Dense 연결용)

2단계 = 사용자 확인·수정 + 검색 쿼리 생성. 코드: `ai/confirm/`, `ai/query/build.py`, `ai/pipeline.py`.

## 1. 호출 순서

```python
p = Pipeline(mock=False)
s = p.prepare(text, profile=None)        # 위기 → 추출 → 세션. 검색 없음
s = p.resume(s, action)                  # 확인 화면 조작, 질문 답. status가 ready가 될 때까지 반복
out = p.search(s)                        # status == "ready"일 때만 검색
found = p.search_queries(bm25_q, dense_q)  # 검색만 확인 (규칙·설명 없음)
```

- `status`: `crisis_stop` / `awaiting_confirm` / `awaiting_answer` / `explore_only` / `ready`
- `ready`가 아니면 `search`는 `{"searched": False, ...}`를 돌려주고 검색하지 않음
- `run(text)`: 사용자 입력 없이 진행. `confirmation: none`, '확인 필요' 영역 미사용
- 확인을 마쳐도 도움 영역이 없으면 욕구 질문 표시. 추출 실패 시 `reason: extract_failed`로 표시하고 `confirm.questions.render`에서 다시 적어 달라는 문구 제공. `extract_status`가 없는 기록은 일반 문구 사용
- 욕구 자유 입력도 추출에 실패하면 같은 질문의 기존 추가 화면에서 도움 영역 선택을 안내. 기존 질문 수 제한과 원문에서 확보한 제약, 활동 범위는 유지

## 2. 검색 모듈로 넘어가는 값

| 키 | 받는 곳 | 형식 | 내용 |
|---|---|---|---|
| `queries.bm25` | `BM25Index.search(문자열)` | str | `사전 토큰. 원문 문장. 접근 긍정어` |
| `queries.bm25_tokens` | 기록용 | list[str] | 의도한 토큰 목록(중복 없음) |
| `queries.bm25_search_tokens` | 기록용 | list[str] | `tokenize(bm25)` 결과(검색 시 실제 토큰) |
| `queries.dense` | `DenseIndex.search(문자열)` | str | 템플릿 문장 |
| `queries.query_mode` | 기록용 | dict | `bm25`: `text`/`template`/`fallback`, `dense`: `text`/`template`, 전환 사유 |
| `queries.access_mode` | 기록용 | str | `A`/`B1`/`B2`/`C` (기본 B1) |

- RRF는 기존 `rrf([bm25_ids, dense_ids], k=rrf_k)` 형식 그대로
- `bm25`는 현재 문자열 인터페이스에 맞춘 임시 연결. 토큰 목록을 직접 받는 검색 함수는 3번 협의 사항

### BM25 쿼리 구성
- 사전: `configs/query_terms.yaml` v0.2(2번 담당 검수 반영, 2026-11-14)
- 사전 토큰: 확정 영역 핵심어(main ≤4, sub ≤2) + 조건부 확장어(main ≤3, sub ≤1). 상한은 `config.yaml stage2.query.caps`, 근거 없는 초기값
  - 무조건 들어가는 핵심어: 주거 [주거], 교육훈련 [학습], 미취업 [취업, 일자리, 구직], 미래설계 [진로]
  - 건강, 경제, 관계참여, 노동, 일상·여가는 핵심어 없음. 원문에 조건 표현이 있을 때만 확장어 추가
  - 확장어는 확정 영역 안에서만 적용. 노동 확장어(근로자, 임금, 산재)는 명시 표현만, 회사·재직 언급만으로는 미적용
- 원문 문장: 제약·활동범위·접근 의도·삭제 영역 evidence 문장을 뺀 나머지를 그대로 넣음
- 접근 긍정어: B1·B2에서만. 상한 2
- 금지어(`재가`, `지원`), 삭제 영역 단어, 회피 채널 토큰(방문·대면, 전화·통화)이 든 문장만 토큰으로 풀어 해당 토큰을 뺌
- 원문에 같은 단어가 반복되면 검색 시 중복 토큰이 생김(`bm25_interface.search_duplicates`에 기록)
- 대체 쿼리(잠정): 사전 토큰과 원문 토큰이 모두 비면 확정 영역 `label_plain` 토큰 사용. `query_mode.bm25 = fallback`, 사유 `empty_need_tokens`, 기록 `query_expansion.bm25_fallback`

### 회피 접근은 쿼리가 아니라 `access`로 전달
- 방문·전화 불가·부담은 BM25·Dense 쿼리 글에 넣지 않음. 규칙 모듈은 `access`(avoid, level 불가|부담)로만 받음. `불가`와 `부담`은 쿼리가 같고 `access.level`만 다름
- 어휘 감지(`build.strip_avoid`): 방문·외출 또는 전화·통화 단서와 부담·불가 표현이 같은 절에 있으면 그 절을 뺌. `전화 말고 문자나 카톡으로`는 `전화 말고`만 뺌. 남은 복지 욕구는 원문과 확장에 사용함
- `방문이 불가능한 건 아니에요`는 제약으로 판정하지 않고 접근 절을 검색에서 제외함. `전화는 못 하는 건 아닌데 되도록 피하고 싶어요`는 전화 부담(선호)으로 처리함
- 추출기 evidence가 없어도 동작: 확인 화면에서 사용자가 추가한 제약, 추출기가 놓친 제약, 일부만 evidence인 경우
- 제약 evidence 문장도 감지되면 회피 절만 빼고 남은 내용을 씀(감지 못하면 이전처럼 문장 통째로 제외)
- 감지된 채널 토큰은 BM25에서 빼고, Dense 문장에서도 채널어를 뺌. 기록은 `query_expansion.lexical_avoid`(`channels`, `clauses`), 제거 문장 `removed_sentences`(reason `avoid_clause`)
- 어휘 감지만으로 `access`를 만들지는 않음(사용자 확인 제약만). 한계: 어휘 사전 밖 표현, 부담어와 채널어가 멀리 떨어진 문장은 못 잡음(잠정 휴리스틱)
- 원하는 접근(want: 온라인·비대면·문자 등)은 이전대로 긍정 표현 허용

### Dense 쿼리 구성
- `{main 쉬운 설명}에 대한 도움을 찾고 있습니다. {sub 설명}도 필요합니다. {원문 문장} {접근 긍정 문장 1개}`
- 부정 표현(없이, 말고, 못, 않, 싫 등)과 접근 채널어(방문·주민센터·전화 등)가 함께 든 문장은 넣지 않음
- 채널어 없는 부정 문장은 유지: '가스비를 아직 못 냈어', '월급을 못 받았어요'처럼 어려움을 말하는 욕구 내용이라서
  (이전에는 부정어만 있어도 빼서 개발 질의 113개 중 28개에서 핵심 문장이 Dense에서 빠졌음)
- Dense 전용 확장: 건강 확정 + 상담 요청 표현이면 `마음이 힘들어서 심리 상담을 받을 수 있는 서비스를 원합니다.` 추가(BM25 미사용, 기록 `query_expansion.dense_only_expansions`)
- 영역 삭제·변경이 있으면 원문 없이 템플릿만

### template 전환 조건
- 삭제·변경 영역 evidence가 남은 영역 evidence와 겹침
- 빼야 할 evidence가 원문 전체, 또는 원문에서 위치를 못 찾음
- 영역 삭제·변경이 있으면 Dense는 항상 template
- BM25가 대체 쿼리를 쓰면 Dense도 template

## 3. 규칙·설명으로 넘어가는 값

- 규칙: `apply_rules(fused, services, rules_view, None)`
  - `rules_view` = `confirmed_profile` 사본 + `access`
  - `stage2.rules_pass.age/region_sido/region_sgg`가 false면 해당 값 None(현재 모두 true)
- 설명: `{"needs": 확정 영역, "activity_range": 확정 활동범위}`
- `access` 항목: `{polarity: avoid|want, channel, level, scope: 신청|이용, mode, pattern_id, source}`
  - `avoid`: 확정 제약(사용자 수정값 포함)
  - `want`: 사용자가 원한다고 쓴 접근 방식
  - B2 추론분은 `access_inferred`(polarity `inferred`)로 따로 둠. 사용자 요청이 아님

### 전달 형식
- `age`: int(10~99). 숫자 문자열 `"23"`은 `rules.normalize.norm_age`로 int 변환. 형식이 맞지 않으면 None
- `region_sido`: `extract.schema.SIDO` 약칭 17개 중 하나(예: `서울`). 서비스 쪽은 `서울특별시` 같은 정식 명칭이라 규칙 모듈이 `norm_sido`로 맞춤
- `region_sgg`: 선택 입력 시군구(예: `노원구`). 확정 시·도에 있는 값만 전달
- `access`: 위 항목 리스트. `rules/access.py`가 제외(필수 확인 + 불가)와 감점에 사용
- 판정 결과: `apply_rules` 반환 항목의 `checks`(`{외출, 연령, 지역, 기간, 접근, 소득}: 통과|확인 필요|제외`), `penalties`(접근·외출 감점)와 `check_reasons`(같은 키, 이유 문장). `excluded=[]`를 넘기면 제외된 서비스도 같은 형식으로 쌓임

### 판정 기준 (`ai/rules/filter.py`, 원칙은 `src/recommend/eligibility.py`와 동일)
| 항목 | 통과 | 확인 필요 | 제외 |
|---|---|---|---|
| 나이 | 서비스 연령 범위 안(경계 포함) | 사용자 나이 없음, 서비스 하한 `N`(원문 근거 없음), 범위 오류(하한 > 상한), 범위 밖이어도 `age_review=True` 또는 `youth_scope_basis`가 `age_may_refer_to_dependent`·`conflict`·`age_partial`, 범위 안이어도 같은 불확실성 | 범위 밖이고 위 불확실성 없음 |
| 지역 | 중앙 사업(`source=central`), 전국, 시도 일치(시군구 없음) | 사용자 시도 없음, 서비스 시도 해석 불가, 시도 일치하나 서비스에 시군구 있고 사용자 시군구 없음 | 시도가 겹치지 않음, 시군구 불일치 |
| 정보 부족 | 해당 없음 | 사용자·서비스 어느 쪽이든 값이 없으면 제외하지 않고 확인 필요 | 해당 없음 |
| 활동범위 | 제외 기준 아님(외출 감점) | 활동범위 없음·판단 불가는 표시만 | 해당 없음 |
- 열린 경계: 상한 `NA`(NaN으로 읽힘)는 상한 없음, 하한 `NA`는 0세. 통합 표기 `전남광주통합특별시`는 광주·전남 모두 일치로 봄

### 규칙 확장 (v2, `ai/rules/`)
| 판정 | 모듈 | 제외 조건 | 그 외 |
|---|---|---|---|
| 지역 | `region.py` | 시·도·시군구 불일치 + 원문에 신청자 본인 거주 요건 명시(거주, 주민등록, 관내 등. '관내 사망자', '관내 소재 기업'처럼 본인 거주가 아닌 표현은 제외 근거로 안 씀) | 거주 요건 불명·다른 자격 경로(재직·재학, 거주 무관 등)는 확인 필요, 사용자 시군구 없으면 확인 필요 |
| 접근 | `access.py` | 방문 불가 + 방문 필수 확인(이용 `use_outing`≥2 근거, 신청 `visit_required_text`·`interview_onsite`) + 원문에 방문 필수·대체 불가 명시(반드시 본인 직접 방문, 대리 신청 불가 등). 대체 경로를 못 찾은 것만으로는 제외하지 않음(현재 해당 0건) | 방문 신청만 안내·필드 없음은 확인 필요, 부담은 감점만, 신청·이용 구분, 온라인 희망은 대체 경로 있으면 가점 |
| 외출 | `outing.py` | 없음 | 활동범위 단계(방 안·집 안 0, 집 근처 1, 필요하면 외출 2)와 `outing_need_min` 차이만큼 감점 |
| 기간 | `period.py` | 사업 종료일(`enfc_end_ymd`) 경과 | 상시·연중·수시, 모집 중은 통과. 모집 시작 전, 모집 종료 추정, 모집기간 원문 없음은 확인 필요(원문 없음은 감점 없음). 연도 없는 반복 기간은 추정 표시 |
| 소득 | `income.py` | 없음 | 정보 표시만(감점 없음). 사용자 소득 미수집 |

- score = 검색 순위 + 영역 불일치 5 + 자격 확인 필요 수(연령·지역·기간) + 접근 감점 + 외출 감점. 가중치는 잠정(`DEFAULT_WEIGHTS`)
- 제외 기록: `search()` 결과 `excluded` = [{servId, rank, checks, check_reasons}]. 카드에 `check_reasons`
- 시군구: 확인 화면 `set_region_sgg`(선택 입력, 질문 수에 안 셈). 확정 시·도에 있는 시군구만 반영, `rules_pass.region_sgg`
- 마스터 전체 점검(25세, 서울 노원구, 방문 불가): 남음 2,224, 제외 3,064(지역 2,969, 연령 317, 기간 1, 접근 0), 연령 원문 없음·중앙 사업 오제외 0
  - DB 전체를 한 사용자 조건으로 판정한 수치. 실제 검색 결과의 추천 정확도·오제외율은 미검증(12·13번 평가 필요)
  - 지역 거주 요건 판정은 표본 약 100건 확인(거주 요건 분류의 약 90%가 실제 요건). '관내 사망자' 같은 신청자 거주와 무관한 문구로 제외될 위험 남음

### U06-009 (수정 없음)

- 확장 적용: 주거비·월세·임차료(주거), 생활비·에너지·긴급생계비 조건 일치(경제). 경제는 sub 상한 1로 생활비만 들어감

### U01-018 (전화 부담 + 문자 요청)
- 원문: 저 이제 27인데 아직 한번도 정규직 해본적이 없어요ㅠ 계약직 끝나고 1년째 쉬는중인데 쉬는게 아니라 그냥 멈춘느낌? 편의점이랑 pc방 가끔 가는거 빼면 집에만 있어요. 근데 전화 오는건 진짜 싫어서 문자나 카톡으로 해주시면 감사하겟습니다ㅜㅜ 일 다시 할수있을지 모르겠어요
- 확정: 미취업(구직)(main), 집 근처, 전화 부담
- BM25: `취업 일자리 구직. 저 이제 27인데 아직 한번도 정규직 해본적이 없어요ㅠ 계약직 끝나고 1년째 쉬는중인데 쉬는게 아니라 그냥 멈춘느낌? 일 다시 할수있을지 모르겠어요`
- Dense: `일자리 찾기와 취업 준비에 대한 도움을 찾고 있습니다. 저 이제 27인데 아직 한번도 정규직 해본적이 없어요ㅠ 계약직 끝나고 1년째 쉬는중인데 쉬는게 아니라 그냥 멈춘느낌? 일 다시 할수있을지 모르겠어요`
- access: avoid 전화 부담. v0.2에서 문자·카톡 요청은 온라인 이용 희망으로 보지 않아 '온라인' 없음
- '전화' 토큰 없음(제약 문장 제외). 회피 절 감지 도입 후에는 이 문장이 통째로 빠지지 않고 `문자나 카톡으로 해주시면 감사하겟습니다ㅜㅜ`가 남을 수 있음(위 BM25·Dense 예시는 도입 전 생성값, 재생성 안 함)
- 원문 속 나이(27)는 원문 문장에 남음. 프로필의 나이·지역을 쿼리에 붙이지는 않음

### U07-010 (대체 쿼리)
- 원문: 만성 통증 때문에 외출은 진료와 취미 수업 정도인데, 상담은 전화보다 메시지가 편합니다.

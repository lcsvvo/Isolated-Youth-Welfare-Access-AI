## 실행 환경

저장소 루트에서 프로젝트 전용 Python 환경을 준비한다. PowerShell 예시는 다음과 같다.

```powershell
py -m venv .venv
$python = '.\.venv\Scripts\python.exe'
& $python -m pip install -r requirements.txt nbconvert
& $python -m ipykernel install --prefix .venv --name q1-local --display-name 'Q1 local'
& $python -X utf8 -m pytest -q
& $python -X utf8 -m jupyter nbconvert --to notebook --execute --inplace notebooks/03_q1.ipynb --ExecutePreprocessor.kernel_name=q1-local --ExecutePreprocessor.timeout=900
```

원문 검수에는 별도로 Claude Code CLI가 필요하다. `claude auth status`로 연결을 확인한다.
CLI가 PATH에 없으면 `--claude`로 실행 파일을 지정한다. Windows에서는 네이티브 `claude.exe`를 지정할 수 있다.
Sonnet과 Opus 연결 및 응답 구조를 표본에서 확인한 뒤 전체 실행을 선택한다.
[Claude Code CLI 공식 문서](https://code.claude.com/docs/en/cli-reference)

```powershell
& $python -X utf8 -m src.labeling.q1_label_audit --plan
```

기본 표본은 ①·② 양성 및 어휘 검색 음성, `age_overlap`, `tag_only`, ⑩ main·candidate, ⑦ self·dependent를 층으로 삼는다. 층별 한 건을 고정 시드로 뽑으며 한 서비스가 여러 층에 걸칠 수 있다. `--per-group`으로 층별 크기를 바꿀 수 있다. 이 표본으로 마스터 전체의 일치율이나 정확도를 추정할 수 없다.

## 판정 및 기록

1. 공개 서비스명·설명·지원대상·선정기준·지원내용·개요·제공유형과 공통 기준만 Sonnet에 전달한다. 이전 라벨 대조는 모델 응답을 받은 뒤 로컬에서 수행한다.
2. 불일치, 판단 불가, 인용 부족은 Opus가 같은 원문으로 독립 재검토한다. 원문 필드에서 찾을 수 있는 인용만 근거로 저장한다.
3. `private/q1_label_audit/audit.sqlite3`에 서비스별 Sonnet·Opus 판정을 각각 저장한다. 같은 명령을 다시 실행하면 저장된 단계부터 이어 간다. 한 체크포인트는 한 프로세스에서 실행한다. 마스터 해시, 검수 버전 또는 모델 버전이 달라지면 `--output`으로 다른 경로를 지정한다.
4. `decisions.csv`에 판정, 기존 라벨, 원문 근거, 항목별 비교, 재검토 필요 여부, 모델과 검수 버전을 내보낸다. 콘솔의 서비스 단위 집계는 Opus 응답이 있으면 그 응답으로, 없으면 Sonnet 응답으로 비교한다. 불일치가 하나라도 있으면 `different`, 그 외 판단 불가가 있으면 `undetermined`, 나머지는 `same`이다. `any_undetermined`는 불일치와 중복될 수 있다.

검수 파일은 로컬에 저장한다. 검수 결과는 팀 검토에 사용하는 후보이며 서비스 마스터와 Q1 집계에는 별도 승인 후 반영한다.

### “시민 누구나”의 청년 범위

서울시 공식 정책 설명은 서울마음편의점의 대상을 외로운 서울시민 누구나로 명시하고, 방문·소통·상담 공간을 제공한다고 안내한다. 이 서비스는 청년 포함과 ① 공간 제공의 명시적 근거가 있다. WLF00006579를 B 후보로 재검토할 근거로 사용할 수 있다. 이는 원문 대상에 대한 연구 운영상의 해석이며 서울시가 A/B/U/C 라벨을 부여했다는 뜻은 아니다. [서울시 정책 아카이브의 서울마음편의점 설명](https://www.seoul.go.kr/policy/view.do?id=1056&lan=KO)

차용할 판정은 다음과 같다.

- 지원대상 전체를 가리키는 전 국민·시민 누구나·모든 연령 등의 표현과 상충하는 필수 연령조건이 없으면 B의 명시적 대상 근거로 기록한다. 근거 종류는 숫자 연령 중첩과 구분해 `universal_target`처럼 기록하고, 원문에 없는 숫자 연령 경계를 만들지 않는다.
- “65세 이상 누구나”, “소득과 관계없이 누구나”처럼 범위가 제한된 표현은 해당 조건과 함께 읽는다. 홍보 문구의 누구나를 서비스 전체의 무조건적 자격으로 확대하지 않는다.
- 원문에 연령조건이 없기만 한 경우에는 U를 유지한다. 서비스 안의 개별 구성요소마다 대상이 다른 경우에도 전체를 B로 바꾸기 전에 적용 대상을 구분한다.

기존 S2_AB_strict는 `age_overlap` 근거만 포함하도록 정의돼 있으므로, 위 근거를 B로 기록해도 자동으로 그 시나리오에 들어가는 것은 아니다. 후속 보조 비교에서는 숫자 연령 근거와 명시적인 전체 대상 근거를 구분해 제시한다. 이 기준은 공통 마스터 반영안과 함께 검토할 수 있으며, 이번 근거 조회에서는 조사 값과 공식 서비스 라벨을 갱신하지 않았다.

보류 9건은 WLF00000982(이송·시설 의뢰의 주거 대응), WLF00001139(연령 종료 시점·지원 세부), WLF00004543(전 연령 대상과 아동청소년 지원내용 충돌), WLF00003232·WLF00005446(농어업 정책보험료의 ⑩ 범위), WLF00004871(학자금 채무조정의 ⑦ 범위), WLF00005855(별도 예외사업 연령을 본 사업 산모에게 적용할 수 없음), WLF00000971(사망자 연령과 유가족 연령 구분), WLF00001303(행사 세부 내용 부족)이다. 이들을 임의로 정답 처리하지 않았다.

전체 대상 표현 5건 중 WLF00001303·WLF00001316·WLF00001450·WLF00001793은 B의 명시적 전체 대상 근거가 있었다. WLF00000971의 연령제한 없음은 사망 보훈대상자 조건이어서 유가족에게 그대로 적용하지 않았다. 앞서 확인한 서울마음편의점과 함께 청년 범위 보완 근거가 있지만 이번 자동 보조안에서는 청년 범위 자체를 바꾸지 않았다. S2_AB_strict의 연령 근거 정의와 686건 분모를 유지한다.

### 5,288건에 적용한 보조 규칙과 결과

`src/gap_index/q1_followup.py`는 서비스 ID별 덮어쓰기 없이 동일한 원문 규칙을 모든 행에 적용한다. 자유 방문 공간, 직접 회복 훈련·자기돌봄비, 일반 돌봄 확장, 응시료 단독과 수강료 병행, 지정 용도 주거·취업 비용, 실제 금융교육·필수 반복비용 지원을 구분한다. 적금과 함께 제공하는 금융교육이나 교육비와 함께 주는 생활보조금 때문에 기존 경제 지원을 지우지 않도록 혼합 급여를 보존한다.

기존 공식 라벨을 출발점으로 확인된 유형만 보정하는 보조 규칙이다. 모든 영역을 처음부터 완전히 재분류하거나 57건 판정을 자동 정답으로 반영한 것은 아니다. 청년 범위와 교육 수혜자의 새로운 수동 판정은 공통 마스터에 반영하지 않는다. 새 ⑦의 수혜자를 자동 규칙으로 확인하지 못하면 N(미상)으로 남긴다. 원래 ⑦이었어도 수혜자 판정이 잘못된 사례는 별도 검토표에 남는다.

S3_ABU에서 ②는 10→5→136건, ⑦은 504→490→490건이다. ①은 6→4→4건이며 서울마음편의점의 공간 근거가 추가되더라도 기존 U를 유지하므로 엄격 시나리오에는 들어가지 않는다. 엄격 시나리오의 ① 0건은 실제 공간 부재의 근거가 될 수 없다. 두 보조안의 큰 ② 차이는 문항 해석의 영향이지 어느 안의 정확도를 입증하는 결과가 아니다.

### 현재 판단

무작위 검토에서도 새 오류 유형이 나왔으므로 기존 29건만으로 Q1 검증이 충분했다는 판단은 유지할 수 없다. 확인된 유형의 전수 자동 보정과 민감도 계산은 완료했지만 정책보험료·학자금 채무조정·대상 충돌의 운영 범위와 보조안 선택은 남아 있다. 이 쟁점을 먼저 보고하고, 범위 검토가 정리되기 전에는 HTML 최종 요약을 작성하지 않는다. 원문 독립 재검토와 자동 테스트 통과를 사람 검수나 전체 분류 정확도의 입증으로 표현하지 않는다.

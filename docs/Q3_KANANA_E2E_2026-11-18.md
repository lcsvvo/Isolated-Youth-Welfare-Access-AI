# Q3 Kanana 포함 전체 추천 검증 (2026-11-18)

## 목적

- 공식 Q3(P@5 0.231)는 사람이 설계한 욕구 라벨과 카드 원문 검색어로 측정한 결과임
- 이번 검증은 독립 평가 카드 80장의 원문만 Kanana에 넣고 위기 판단 → 추출 → 행동 결정 → 검색어 생성 → BM25·BGE-M3 → RRF → 자격 규칙 → 관련성 선별 → 추천(최대 5개)까지 실제 `Pipeline` 경로를 실행함
- 기존 Q3 검색 32장 결과와 나머지 48장을 구분해 기록함

## 실행 조건

- Kanana `kanana-2-3b-instruct`, Colab T4, 1회 추출(코드 `15e79a3` 고정). 겹치는 32장은 이전 추출과 출력 32/32 동일
- 코드 버전별 비교는 같은 Kanana 원래 출력에 각 버전의 후처리·검색을 다시 적용
- C3: `pipeline.run`과 같은 자동 실행(사용자 확인 없음)
- C3Q: 욕구가 없을 때 앱 확인 질문에 설계 주욕구로 답한 시뮬레이션
- 기준일 2026-11-14

## 확인된 문제와 원인

- 욕구 미검출 → 검색 없이 종료
  - 구어체 요청("잇나여")을 요청 게이트가 인식하지 못해 맞게 추출한 욕구까지 삭제
  - 요청 없는 상태 서술은 설계대로 욕구를 비움 → 확인 질문에 후보 힌트가 없음
- 검색어 생성에서 활동·제약 문장을 통째로 삭제해 욕구·상황 단서 손실
- 활동 근거가 문장 전체: 후처리 `rule_activity`가 원인(프롬프트·few-shot 수정으로는 개선 안 됨)

## 수정 사항

- `ai/extract/postprocess.py`
  - 구어체·오타 요청 표현 인식
  - 요청 없는 욕구는 삭제하지 않고 `확인 필요`로 강등(자동 실행 미사용, 확인 단계 후보)
  - 직접 요청한 검진·수면 상담·생활습관 개선 누락 시 영역 복원(#121)
  - 그래도 욕구가 없으면 상태 서술 단서로 최대 2개 영역을 `확인 필요` 후보로 추가. 원하지 않는다는 문장·다른 사람의 바람은 제외
  - 활동 근거를 절 단위로 축소(활동 범위 판정 불변)
- `ai/query/build.py`: 활동 문장·욕구 근거 문장은 구절만 제거. 교육 요청·과목명 보존, CAD·컴활 표기 처리(#121)
- `ai/pipeline.py`: `Pipeline.explore(session, limit)` — 욕구 없는 세션의 원문 검색 + 자격·접근 규칙(탐색용·순위 아님)

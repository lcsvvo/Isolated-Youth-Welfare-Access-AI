카나나는 **이미 연결되어 있고, Colab T4에서 실제 실행까지 확인된 상태**예요. 지금 필요한 건 새 연결이나 재학습보다는 **최신 코드 반영과 동작 점검**입니다.

구분하면 이래요.

| 바뀐 내용 | 필요한 작업 |
|---|---|
| 글씨·배치·스크롤 등 화면 | 최신 코드 받기 → Streamlit 재시작 |
| 카나나 프롬프트·추론 설정·파이프라인 | 최신 코드 받기 → 파이프라인/모델을 사용하는 앱 재시작 → 답변 확인 |
| 복지 CSV·검색 데이터 | 데이터 반영 → 검색 색인·임베딩 캐시 갱신 여부 확인 → 앱 재시작 |
| Colab 런타임 종료 | GPU·환경·모델을 다시 불러와 실행 |

**엉뚱한 복지 서비스가 나오는 문제를 카나나 업데이트만으로 해결할 수는 없어요.** 이 서비스는 카나나의 입력 해석, bge-m3·BM25 검색, 지역·나이 등 조건 필터, 원본 데이터가 함께 작동합니다. 이상한 결과가 나온 입력을 재현해서 어느 단계에서 어긋났는지 확인해야 해요.

속도도 **모델 초기 로딩 / 입력 해석 / 검색 / 상세 설명 / Gemini 응답**을 나눠 측정해야 합니다. Gemini는 일상 대화용으로 별도 연결돼 있어서, 켰을 때 느려진 문제도 카나나와 구분해서 봐야 하고요.

현재로서는 **카나나를 다시 연결하거나 학습시키기보다, 기존 연결을 유지한 채 추천 오류와 지연 원인을 먼저 확인하는 게 맞습니다.**

| API·키 | 연결할 곳 | 현재 상태 |
|---|---|---|
| **Gemini** — `GEMINI_API_KEY` | “안녕하세요” 같은 일상 대화 → `ai/chitchat.py` | 호출 코드 있음. 실제 키로 재검증 필요 |

| **보조금24** — `GOV24_API_KEY` | 서비스 정보 수집·출처 비교 갱신 | 위와 같음 |
| **GitHub** — `GH_TOKEN` | Colab에서 비공개 저장소 받기 | 모델용 키가 아님. 이미 다운로드되면 새 발급 불필요 |
| **Kanana·BGE-M3** | Colab 안에서 모델을 직접 실행 | 현재 구조에서는 별도 API 키 불필요 |
| **OpenAI** | 과거 공고 구조화 후보로 검토 | 현재 호출 코드 없음. 지금 발급할 필요 없음 |

노션의 [Streamlit 작업 문서](https://app.notion.com/p/Streamlit-41adad625c5e80deb27cd3a8b3f0763c)에도 **개인 Gemini 키를 Colab에 넣고 테스트하는 작업**이 남아 있습니다. [전체 파이프라인 문서](https://app.notion.com/p/419dad625c5e80068adbf2faf772bc62)는 **복지 정보 자동 갱신이 미구현**이라고 구분하고 있어요.

**먼저 Gemini는 이렇게 준비하면 됩니다.**

1. [Google AI Studio의 API 키 화면](https://aistudio.google.com/apikey)에 로그인합니다.
2. **Create API key**로 본인 프로젝트의 키를 발급받습니다. 기존 키가 있으면 사용할 수 있는지 확인하면 됩니다. [공식 안내](https://ai.google.dev/gemini-api/docs/api-key)
3. 본인 Colab 노트북 왼쪽 **열쇠 아이콘 → 보안 비밀**에 저장합니다.
   - 이름: `GEMINI_API_KEY`
   - 값: 발급받은 키
   - **노트북 액세스 켜기**
4. 첫 설정 셀과 앱 실행 셀을 다시 실행합니다. 현재 노트북은 이 키를 읽도록 구현돼 있습니다.

**복지 정보 자동 갱신용으로는 아래 세 서비스를 준비하면 됩니다.**

| 공공데이터포털에서 활용 신청할 서비스 | 저장할 이름 | 현재 수집기가 사용하는 키 형식 |
|---|---|---|
| [한국사회보장정보원_중앙부처복지서비스](https://www.data.go.kr/data/15090532/openapi.do) | `CENTRAL_KEY` | Decoding |
| [한국사회보장정보원_지자체복지서비스](https://www.data.go.kr/data/15108347/openapi.do) | `LOCAL_KEY` | Decoding |
| [행정안전부_대한민국 공공서비스(혜택) 정보](https://www.data.go.kr/data/15113968/openapi.do) | `GOV24_API_KEY` | Encoding |

공공데이터포털 로그인 → 각 서비스 **활용 신청 → 승인 확인 → 인증키 확인** 순서입니다. 이미 팀에서 승인받은 계정이 있다면 새로 수집용 계정을 만들기 전에 그 상태부터 확인하면 됩니다.

다만 **공공 키를 넣는 것만으로 자동 갱신이 완성되지는 않습니다.** 수집기 설정을 맞추고, 변경 감지·데이터 검증·검색 색인 갱신·화면 반영을 연결해야 합니다. 기존 최종 CSV로 추천을 시연하는 데는 이 공공 키들이 필요하지 않습니다.

**키 값은 저에게 채팅으로 보내지 마세요.** 본인 Colab 보안 비밀에 저장한 뒤 **“Gemini 저장 완료”, “공공 API 세 개 승인·저장 완료”처럼 상태만 알려주시면 됩니다.** 공공 키 세 개를 Colab에서 읽어 갱신에 사용하는 코드는 아직 추가해야 합니다.

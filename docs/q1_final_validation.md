# Q1 독립 재판정 결과 — 30건 한정 검증

30건의 독립 재판정과 조건부 결과 영향 계산을 마쳤다. 추가 표본을 늘리지 않는다. 다만 해석 차이를 함께 반영한 경우 경제 영역이 공급 순위 공동 3위에 들어가므로, 사전 중단 규칙에 따라 **최종 HTML과 Q1 전체 완료 선언은 보류**한다. 이는 전체 분류 품질 평가가 아니라 확정된 30건·총 40회 이내에서 발견 가능한 위험을 점검한 결과다.

## 표본과 독립성

- 브랜치: `feature/q1-main-analysis`, 기존 PR #11. Q2와 공통 마스터는 변경하지 않는다.
- 고정 시드: `2026110501`. 기존 29건·57건, 앞선 모델 판정 및 코드·문서에서 개발에 지목한 사례, 일괄 확인한 응시료·경제 제외 사례 등을 합해 211개 ID를 보수적으로 제외했다.
- 새 표본: 30개 고유 서비스. 보조 규칙 변경 15건, 미변경 15건. 기존 S2_AB_strict 포함 12건, 그 밖 18건이다.
- 변경 집단: 돌봄 확장 8건·교육 7건. 미변경 집단: 공간 어휘 인접 4건, 회복 어휘 인접 3건, 교육 양성/음성 각 2건, 경제 main/candidate 각 2건.
- ① 양성과 ⑩ 변경 사례는 제외 후 적격 사례가 없어 새 양성·변경 검증을 할 수 없었다. ①은 어휘 인접 음성의 누락 가능성만 점검하며, ⑩은 소수 미변경 사례 점검이다. 직접 회복 ②의 새 양성을 독립 검증한 것으로도 표현하지 않는다.

`private/q1_final_audit/manifest.json`에 표본·제외 ID·고정 시각·기준·원문·마스터·개발 규칙 해시를 저장했다. 기준은 첫 Sonnet 요청 전에 고정했다. 설계 보완 전 버전도 보존했다. `sources.json`은 원문, `sealed_rule_outputs.json`은 로컬 대조 전용 규칙 스냅샷이다.

사례 모델에는 원문 필드와 코드북·고정 기준만 전달했다. 서비스 ID, 층 이름, 기존 라벨, 보조 규칙 결과, ID별 수정 내역, 다른 모델 답변은 전달하지 않았다. 도구·MCP·세션 지속·자동 메모리를 끄고 저장소 밖 임시 디렉터리의 별도 컨텍스트에서 1턴씩 요청했다.

Sonnet 30건 전부 저장 후에만 재검토 선정을 위한 로컬 대조를 열었다. 우선순위는 `10×불일치 여부 + 5×참조 칸 불일치 여부 + 2×판단 불가 여부 + 근거 문제 여부`이며 모두 불리언 값이다. 동점은 ID 정렬, 상한은 6건이다. Opus 사례 판정이 모두 저장된 뒤 최종 비교표를 내보냈다. Opus는 정답 판정자가 아니다.

## 역할과 사용량

실제 실행 모델은 Sonnet `claude-sonnet-5`, Opus `claude-opus-5`다. 세부 요청·응답·토큰·CLI 보고 비용·소요시간은 `calls.sqlite3`, `usage.csv`에 보존한다. 실패·예약 상태도 40회 예산에 포함하며 자동 재시도하지 않는다.

| 역할 | 호출 수 | 목적 |
| --- | ---: | --- |
| Sonnet | 30 | 원문 기반 독립 판정·근거 추출 |
| Opus 설계 검토 | 2 | 기준·판정 불가 사유·격리·중단 절차 점검 |
| Opus 사례 재검토 | 6 | 고정 우선순위의 중요한 불일치·판단 불가 |
| Opus 최종 해석 검토 | 2 | 불일치 분류·영향·보고 논리 점검 및 순위 범위 명시 |
| 합계 | 40 | 상한 40회에서 종료, 추가 표본 없음 |

설계 검토 두 번은 모두 포괄적인 `ready=false`를 반환했다. 지적 중 코드 정의·단일 출력 스키마·unknown 사유·음성 근거·해시·재검토 선정 절차는 첫 Sonnet 전에 보완했다. 이미 구현한 해시를 확인하지 못한 지적, ① 음성 표본의 점검 방향을 반대로 설명한 지적 등은 근거를 남겨 채택하지 않았다. 적은 표본의 구조적 한계는 그대로 기록하고 진행했으며 **설계가 Opus 인증을 통과했다고 주장하지 않는다.** 처리는 `design_review_v1.json`, `design_review.json`, `design_resolution.json`에 있다.

## 새 유형의 규모와 조건부 영향

`src/gap_index/q1_audit_impact.py`가 명시한 실제 지원내용 어휘로 후보 행을 찾고 원래 5,288건 사본에서 계산했다. **아래는 같은 어휘 조건에 걸리는 변경 후보 수이며, 확인된 오류 수나 의미상 가능한 전체 상한이 아니다.** 표본 불일치를 5,288건으로 비례 확대하지 않았다. 공식·개발 보조 규칙과 원자료는 그대로 두었다.

이 영향 계산의 어휘 조건은 재판정 결과를 보고 만든 반사실 대안이다. 최초 고정한 개발 보조 규칙의 독립 점검과 구분하며, 대안까지 이 30건으로 독립 검증했다고 표현하지 않는다.

| 가정 | 전체 변경 후보 | 참조 칸 후보 | S3_ABU 후보 |
| --- | ---: | ---: | ---: |
| 양육보조금의 main 대응 | 19 | 6 | 13 |
| 월 정기 자립지원수당의 main 대응 | 2 | 1 | 2 |
| 귀향여비·장제비의 candidate 대응 | 86 | 3 | 85 |
| 별도 교육비 근거 없는 입학축하금의 ⑦ 제외 | 16 | 1 | 14 |
| 급식·숙식·가사도우미·이동서비스의 care 어휘 확장 | 42 | 7 | 37 |

귀향여비·장제비는 지급 근거가 benefit에 있는 좁은 조건만 계산했다. target/criteria에만 지원내용이 있는 경우까지 모두 찾아낸 수치는 아니다. 현금 양육 지원을 care로 보는 추가 해석도 이번 자동 어휘 영향에 모두 포함하지 않았다. 따라서 조건부 민감도를 의미상 누락 전체의 완전한 경계로 표현하지 않는다.

| S2_AB_strict × v4_main | 개발 보조안 | 관찰 유형별 대안 | 해석 차이를 함께 둔 대안 |
| --- | ---: | ---: | ---: |
| ① 공간 | 0 | 0 | 0 |
| ② 직접 회복 | 2 | 2 | 2 |
| ② 돌봄 확장 | 20 | 27 | 27 |
| ⑦ 교육 | 82 | 81 | 81 |
| ⑩ main | 41 | 양육보조금 47 / 정기 수당 42 | 48 |
| ⑩ 공급 순위 | 4 | 각각 4 | 공동 3 |
| 직접 회복안의 수요 매우 필요율–후보 수 Spearman | 0.558 | 각각 0.558 | 0.572 |

각 경계 하나만 바꾸면 상위 3위 집합은 유지된다. 해석을 결합했을 때만 ⑩ 48건이 ③ 48건과 동률이 되어 상위 3개 순위 집합(동률로 4개 영역)에 ⑩이 추가된다. 47건이면 이런 변화가 없으므로 단 1건에 좌우되는 경계다. 사전에 정한 안정성 점검을 결합 가능 범위까지 보수적으로 적용해 HTML을 보류하며, 이를 공급 순위의 실질적인 변화로 단정하지 않는다. ①의 0건 여부와 ② 직접 회복 2건은 이 조건부 계산들에서 바뀌지 않았지만, 독립 양성 부재로 실제 공백 여부는 여전히 미확인이다.

후보 규모와 결과 효과는 구분한다. 참조 칸에서 양육보조금 후보 6건은 main에 +6, 정기 수당 1건은 main에 +1이다. 귀향 비용 후보 3건은 candidate에만 +3이므로 main에는 영향이 없다. 입학축하금 1건은 ⑦에서만 -1이고 기존 경제 candidate는 보존한다. 돌봄 어휘 후보 7건은 확장 ②에만 +7이며 핵심 ②에는 영향이 없다. 후보별 ID와 원문은 `final_audit_impact_candidates.csv`에 보존했다.

이 순위는 조사 문항이 있는 10개 영역 안에서 매긴다. ⑪ 주거는 조사 문항이 없어 후보 수만 별도로 보존하며 순위 비교에서 제외한다. 첫 Opus 해석 검토는 이 범위 설명이 부족한 입력에서 ⑪을 포함해 순위를 지적했다. 기존 코드의 `DEMAND_AREAS=AREAS[:10]`과 기준쌍(직접 회복안끼리, 돌봄 확장안끼리)을 명시해 마지막 1회로 다시 확인했다. 모델 지적도 코드·정의와 대조하며 자동으로 채택하지 않았다.

참조 칸의 여덟 조건부 대안에서 Spearman은 0.558~0.683이다. 모두 양의 기술적 순위 대응이지만 이 범위는 신뢰구간·모집단 추정·분류 적절성의 증거가 아니다.

마지막 Opus 해석 검토는 위 정의를 명시한 후 `logically_supported=true`, `stop_or_continue=stop`, `html_ready=false`를 반환했다. 단일 경계와 결합 경계, 1건 동률의 취약성, 후보 수와 실제 계수 변화의 구분을 보고서에 반영했다. 이것도 모델의 논리 검토 결과이며 사람 승인이나 전체 분류 품질의 인증은 아니다.

S3_ABU의 돌봄 확장은 136→173건, 입학축하금 제외 시 교육은 490→476건, 양육보조금 main 대응 시 경제는 428→441건이며 정기 수당까지 함께 두면 443건이다. 이는 정의·어휘의 효과이지 실제 서비스 정원이나 청년 접근 가능성의 변화가 아니다.

모델 단계는 저장 응답을 재사용하며 실패를 자동 재시도하지 않는다. 최초 실행의 사전 설계 보완·영향 해석 입력은 로컬 manifest·resolution·interpretation 기록을 함께 읽어야 한다. 이를 일괄 자동 정답 생성 절차로 제공하지 않는다. 자동 영향 계산은 개인 판정 파일 없이도 같은 마스터·개발 규칙에서 재현할 수 있다.

- `private/q1_final_audit/`: 기준·표본·원문·규칙 스냅샷·원응답·호출 장부·모델별 비교·원인 분류·해석 검토.
- `outputs/03_q1/tables/final_audit_type_counts.csv`: 어휘별 후보 규모.
- `outputs/03_q1/tables/final_audit_impact_candidates.csv`: 조건부 후보 ID·원문.
- `outputs/03_q1/tables/final_audit_impact_supply.csv`, `final_audit_impact_rank.csv`: 시나리오·경제 기준·반사실별 후보 수와 순위.

생성 결과와 판정 데이터는 로컬에 보존한다. 커밋은 재현 코드·필요 테스트·이 기술 보고서에 한정한다. 전체 정확도·정밀도·재현율·사람 검증 완료를 주장하지 않는다.

호출 한도·동결 응답 재사용·미완료 판정의 대조 잠금과 기존 보조 규칙을 확인하는 필요한 테스트 8개가 통과했다. 이후 추가 검증을 중단하라는 요청에 따라 테스트·표본·모델 호출을 더 늘리지 않는다.

## 남은 결정과 종료 범위

추가 검수는 여기서 중단한다. 남은 것은 더 많은 사례를 무조건 검수하는 일이 아니라 **양육보조금·정기 자립지원수당의 main 기준, 현물·비용 보전을 포함한 care 범위, 용도 미상 입학축하금의 교육 대응**을 일관되게 정하는 일이다. 귀향여비 등 반복 생활비가 아닌 목적 비용도 같은 기준에 연결해야 한다.

이번 독립 검증은 완료했지만 Q1 전체 완료·최종 HTML은 아직 보류다. 운영 기준이 정리되면 기존 후보 표와 조건부 대안을 하나의 보고 원칙으로 묶고 HTML을 작성한다. 자동 테스트 통과와 모델 간 일치는 이 결정을 대신하지 않는다.

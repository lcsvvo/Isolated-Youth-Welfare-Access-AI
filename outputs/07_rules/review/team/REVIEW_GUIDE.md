# 규칙 조건 검수 가이드

추천 규칙이 서비스를 잘못 제외하지 않도록, 서비스 원문의 연령, 지역, 접근 조건을 사람이 확인하는 작업

## 1. 내 파일

| 파일 | 연령 | 지역 | 접근 | 합계 |
|---|---:|---:|---:|---:|
| `R1.csv` | 15 | 20 | 25 | 60 |
| `R2.csv` | 15 | 20 | 25 | 60 |
| `R3.csv` | 15 | 20 | 25 | 60 |
| `R4.csv` | 15 | 20 | 25 | 60 |
| 합계 | 60 | 80 | 100 | 240 |

- 엑셀로 열어도 한글 깨짐 없음(UTF-8 BOM)
- 여러 유형에 선정된 서비스는 같은 파일에 연속 배치
- 원본 365행(연령 93행, 지역 101행, 접근 171행) 보존. 미선정 125행은 기존 상태 유지
- 서비스마스터의 지원 대상과 지원 내용에서 청년 특화 서비스와 청년이 이용할 수 있는 일반 복지서비스 우선 선정
- 신청자와 가구원의 연령, 거주·재직·재학의 결합, 신청·이용 및 방문 주체와 대체 경로가 혼동될 수 있는 사례 우선 선정. 조건이 명확한 사례도 포함해 기존 제안을 점검
- 검수자별 욕구 영역과 난이도 분산. `selection.csv`의 `prio`는 1(명시 조건 대조)부터 3(조건 또는 적용 주체 구분)까지의 상대 난이도
- 오류 발견과 규칙 보완을 위한 우선 검수이며 전체 서비스마스터의 추천 정확도와 오제외율을 추정할 수 없음

## 2. 작업 순서

1. `review_type`(연령, 지역, 접근) 확인
2. `입력할_칸`에 적힌 칸만 채움
3. `검수_대상_원문`을 읽고 판단. 원문만으로 부족하면 `servId`로 복지로·정부24 공식 안내 확인
4. `AI_제안`은 참고만 함. 틀렸으면 그대로 따르지 않음
5. `reason`에 근거 한 줄, `reviewer`에 이름, `reviewed_at`에 날짜(`2026-11-20` 형식) 입력
6. CSV 형식 그대로 저장. 열 이름, 행 순서, `servId` 수정 금지

## 3. 칸 채우는 법

### 연령: `decision`, `human_min`, `human_max`

| decision | 언제 | 나이 칸 |
|---|---|---|
| 유지 | AI가 뽑은 연령이 신청자 본인 연령으로 맞음 | 비움 |
| 수정 | 연령 조건은 있으나 숫자가 틀림 | 맞는 나이 입력 |
| 제외 | 신청자 연령이 아님(자녀, 유족, 부양가족 나이 등) | 비움 |
| 보류 | 원문과 공식 안내로도 판단 불가 | 비움 |

- 나이는 정수만 입력, 상한이나 하한이 없으면 그 칸 비움. 예: `19세 이상` → min 19, max 빈칸
- '연령 제한 없음' 후보는 정말 제한이 없으면 유지

### 지역: `region_rule`, `region_area`

| region_rule | 예시 원문 |
|---|---|
| 거주 필수 | 서울시 거주 청년, 노원구에 주민등록을 둔 자 |
| 거주 또는 재직·재학 | 안산시 거주 또는 재직 청년 |
| 신청자 거주 조건 아님 | 관내 사망자의 유족, 장애인거주시설 이용자 |
| 지역 제한 없음 | 전국 청년 누구나 |
| 거주 조건 불명 | 서울 소재 상담센터 이용(거주 요건 언급 없음) |

- 핵심 질문: 신청자가 그 지역에 살아야 신청할 수 있는가
- 서비스를 제공하는 지역과 신청 자격 지역을 구분
- `region_area`: 거주 조건의 지역 이름(예: `안산시`). 없으면 비움

### 접근: `apply_visit`, `apply_alt`, `use_visit`, `use_alt`

신청과 이용을 따로 판단

| 칸 | 값 | 뜻 |
|---|---|---|
| apply_visit | 필수, 선택, 불필요, 불명 | 신청할 때 직접 가야 하는지 |
| apply_alt | 있음, 없음 명시, 불명 | 온라인, 전화, 우편, 대리 신청 등 다른 신청 방법 |
| use_visit | 사용자 방문 필수, 담당자 방문, 선택, 불필요, 불명 | 서비스를 받을 때 사용자가 가야 하는지 |
| use_alt | 있음, 없음 명시, 불명 | 비대면, 찾아가는 서비스 등 다른 이용 방법 |

| 원문 | 입력 |
|---|---|
| 반드시 본인 직접 방문, 대리 신청 불가 | apply_visit 필수, apply_alt 없음 명시 |
| 온라인 또는 방문 신청 | apply_visit 선택, apply_alt 있음 |
| 온라인 신청 후 센터 방문 필수 | apply_visit 불필요, use_visit 사용자 방문 필수 |
| 상담원이 집으로 방문 | use_visit 담당자 방문 |
| 방문 신청만 안내 | apply_visit 불명, apply_alt 불명 |

- '방문'이라는 단어가 있어도 누가 가는지 확인. 담당자가 오면 사용자는 외출 불필요
- '없음 명시'는 원문에 대체 방법이 없다고 적힌 경우만. 찾지 못했으면 불명

## 4. 주의

- 값은 표에 있는 단어 그대로 입력. 띄어쓰기 포함
- `-` 칸은 다른 유형의 칸. 비워 두거나 지우지 않음
- 판단이 어려우면 연령은 보류, 지역은 거주 조건 불명, 접근은 불명 선택. 추측해서 채우지 않음
- 일부 칸만 채운 행은 반영되지 않음

## 5. 반영

- 제출된 파일은 `python -m ai.eval.rules_team_review merge`로 확인 후 `--apply`로 기존 검수 시트에 반영
- 기존 시트에 이미 값이 있으면 덮어쓰지 않고 충돌로 기록
- 반영 후 `python -m ai.eval.rules_overlay_compare`로 판정 변화 확인. 전체 테스트 재실행 후 PR 최종 검토에서 병합 여부 결정
